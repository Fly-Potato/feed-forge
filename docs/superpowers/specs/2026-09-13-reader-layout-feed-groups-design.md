# 阅读器布局、局部刷新与订阅分组设计

日期：2026-09-13

## 目标与范围

优化 Feed Forge 主阅读器的空间利用和操作归属：删除阅读器内容区现有的应用级 Header，把设置入口移到订阅源侧栏底部，在订阅源和文章列表各自的标题栏提供窄版图标刷新按钮，并把扁平订阅源列表升级为最多两级的“分组 → 订阅源”树。

二级节点的业务含义固定为：一级节点是用户创建的订阅分组，二级节点是可选择的订阅源；分组不能包含分组，订阅源不能包含子节点。现有订阅在迁移后归入系统生成的展示节点“未分组”。本次不增加拖拽排序、任意深度目录、跨窗口同步协调或展开状态持久化。

`docs/testing-strategy.md` 仍是当前测试规范的唯一权威来源。本设计不改变测试栈，也未产生新的路线图触发条件。

## 主窗口布局

保留现有 `AppTitleBar` 和三栏网格，删除 `ReaderPage` 中包含“Feed Forge / 本地 RSS 阅读器”、同步状态、文字刷新按钮和设置按钮的内容 Header。三栏网格直接占用窗口标题栏以下的全部可用高度，现有自动折叠断点和 48px 折叠宽度保持不变。

订阅源栏采用固定顶部工具栏、可滚动树区和固定底部工具栏：

- 顶部左侧显示“订阅源”，右侧依次为“同步全部订阅源”和折叠按钮。
- 底部放置仅显示齿轮图标的设置入口；它是全局设置入口，但依附于永久存在的应用导航栏，不依赖仅在部分平台显示的自定义窗口标题栏。
- 订阅源栏折叠后，顶部纵向保留同步与展开按钮，底部保留设置按钮，确保核心操作仍可达。

文章列表栏只保留一个顶部工具栏，避免现有外层折叠栏与 `ArticleList` 内层标题栏重复：左侧显示“文章”和“全部 / 未读 / 收藏”筛选，右侧依次为“同步当前订阅源”和折叠按钮。未选择订阅源时，当前订阅刷新按钮禁用；加载、空状态和错误状态都保留同一标题栏，防止页面跳动。

刷新、设置和折叠按钮统一复用项目现有 shadcn Button，使用 `variant="ghost"`、`size="icon-sm"` 和 Lucide 图标。图标按钮必须提供准确的 `aria-label` 和悬停提示；图标本身对辅助技术隐藏。刷新运行时只让触发任务的刷新图标旋转，两个刷新入口共同禁用，避免同一页面并发启动同步任务。动画需尊重 reduced-motion。

## 刷新语义与反馈

两个刷新入口都表示从网络同步 RSS，不调用仅重新读取本地 Query 缓存的 `useFeeds.refresh` 或 `useArticles.refresh`：

- 订阅源栏刷新调用 `sync.start()`，同步全部订阅源。
- 文章栏刷新调用 `sync.start(selectedFeedId)`，只同步当前订阅源。

自动刷新定时器、两个手动入口共用同一个 `useSync` 实例和运行中门禁。`useSync` 增加明确的运行状态和本次目标作用域；从发起命令开始到首次有效 `completed`、`failed` 或 `canceled` 终态期间拒绝页面内的重复启动。该门禁解决本次新增入口的重复点击问题，但不扩展为跨窗口或后端全局单任务策略。

现有同步终态语义保持不变：有效终态失效 feeds 和 articles 查询，过期或畸形 Channel 消息不能触发刷新。同步进度或错误显示在发起刷新所在面板的标题栏下方；面板折叠时至少保留图标状态和 `aria-live` 状态通知，不能因删除主 Header 而丢失错误反馈。终态继续区分完成、失败与取消。

## 订阅分组数据模型

新增数据库迁移，创建 `feed_groups` 表，至少包含稳定整数 ID、非空名称和创建时间；名称按大小写不敏感规则唯一。`feeds` 表增加可空的 `group_id` 外键并建立索引，外键引用 `feed_groups(id)`，删除分组时使用 `ON DELETE SET NULL`。这样删除分组只把其中订阅移到“未分组”，不会删除订阅或文章。

`feed_groups` 不包含 `parent_id`，数据库和服务层都不存在创建子分组的入口，从结构上保证最多两级。现有订阅的 `group_id` 为 `NULL`，无需数据回填。分组和同组订阅暂按名称不区分大小写排序，不增加 `sort_order`。

Rust 与前端契约增加 `FeedGroup`，现有 `FeedSummary` 增加可空的 `groupId`。保留已有 `feeds_list`、`feeds_add`、`feeds_update` 和 `feeds_remove` 命令的职责；新增分组列表、创建、重命名、删除命令，以及独立的订阅移动命令。新增订阅允许携带可空 `groupId`；移动命令显式接受 `groupId: number | null`，避免把“没有更新该字段”和“移回未分组”混为一谈。

服务层在创建、重命名和移动前验证去除首尾空格后的非空名称、分组存在性及大小写不敏感重复；数据库约束和外键只作为最终一致性保护。所有新 command 保持薄适配，业务规则放在 feeds service/repository，错误映射为稳定、安全的 IPC 错误，不向前端暴露 SQL 细节。

## 前端树与订阅管理

`useFeeds` 同时维护订阅源和分组 Query，分组或归属 mutation 完成功后失效相应 feeds keys；订阅增删改仍保持现有缓存一致性和选择清理语义。由 feeds 模块内的纯函数将 `FeedGroup[] + FeedSummary[]` 转换为展示树，生成真实分组节点和一个仅在存在未分组订阅时出现的合成“未分组”节点。

`FeedList` 使用语义化二级树：根列表使用 `role="tree"`，分组节点使用 `role="treeitem"` 和 `aria-expanded`，子列表使用 `role="group"`，订阅叶节点使用 `aria-selected`。每个真实分组使用独立 Collapsible，默认展开；展开状态只存在当前页面生命周期。点击分组只展开或收起，点击订阅才修改 `selectedFeedId`。现有订阅标题和 URL 信息保留，但通过缩进、文件夹/展开图标和紧凑间距表达层级。

设置弹窗的“订阅管理”页增加最小完整管理能力：创建、重命名和删除分组；新增订阅时可选择分组；现有订阅可移动到其他分组或“未分组”。删除分组前明确提示其中订阅会保留并移动到“未分组”。本次不支持在主树中拖拽、内联改名或右键菜单，避免把阅读导航与管理操作混在一起。

## OPML 兼容

现有 OPML 解析会递归读取任意层级的 feed outline，但丢弃父级信息。本次改为保留可表示的两级结构：body 下的非 feed outline 作为一级分组，其后代 feed outline 都归入该顶层分组；body 下直接出现的 feed 保持未分组。超过两级的 OPML 目录被确定性压平到最外层分组，不创建第三级，也不因常见的深层 OPML 文件而拒绝整个导入。

导入时先按名称复用或创建分组，再插入订阅；URL 已存在时继续计为 skipped，不自动移动用户已有订阅。导出时真实分组输出为包含 feed outline 的一级 outline，未分组订阅直接输出在 body 下。空分组不导出，因为它不包含可交换的订阅数据。

## 错误与边界行为

- 分组名为空或大小写不敏感重复时拒绝保存，并在当前表单附近显示安全错误。
- 向不存在的分组移动订阅时返回 not-found 类错误，原归属不变。
- 删除当前选中订阅所在分组不会清除文章选择，因为订阅本身仍存在；删除订阅仍沿用现有选择清理。
- 分组列表读取失败时不把所有订阅永久视作未分组；界面展示错误并允许 Query 后续重新获取。
- 同步失败或取消后仍失效缓存，因为此前成功处理的订阅已经逐项提交。
- 文章栏刷新在未选择订阅、同步运行中或目标订阅已从成功查询结果消失时不可触发。

## 测试与验收

按测试驱动顺序覆盖下列行为：

1. Rust 迁移和 service 测试：创建分组表与外键、现有订阅保持未分组、分组增删改、重复名称、移动和清空归属、删除分组保留订阅。
2. OPML 测试：两级分组导入导出、深层目录压平、根级订阅保持未分组、重复 URL 不移动已有订阅。
3. 前端 schema/IPC/hook 测试：`groupId` 和分组 DTO 校验、新 command 名与输入、成功及畸形响应、mutation 后缓存失效。
4. `FeedList` 组件测试：树和 group 语义、默认展开、分组折叠、叶节点选择、“未分组”合成节点、严格两级展示。
5. `ReaderPage` 测试：内容 Header 消失、设置入口新位置、两个图标刷新按钮的作用域、无选择禁用、运行中防重复、终态后的状态和缓存更新、折叠模式下操作可达。
6. 设置订阅管理测试：分组 CRUD、订阅分配与移回未分组、删除提示与忙碌状态。

这是跨前后端与数据库迁移的变更，验收运行 `pnpm test:all`、`pnpm build`、`cargo check --manifest-path src-tauri/Cargo.toml` 和 `git diff --check`，并人工检查默认窗口宽度、两个侧栏折叠状态、键盘焦点、浅色/深色主题以及同步状态反馈。mock 与 jsdom 全绿不能替代打包桌面窗口的最终布局检查。
